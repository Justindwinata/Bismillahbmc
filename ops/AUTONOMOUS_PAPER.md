# Autonomous PAPER / SHADOW operating slice

Mainnet signing and real spending remain disabled. This is not a strategy edge or live execution qualification.

Start PostgreSQL, migrate, then `pnpm dev:local` using ops/DEVELOPMENT.md. Worker now runs a PAPER scheduler independently of the market polling loop and browser. Open `/paper`, review the versioned virtual policy and virtual capital, choose PAPER or SHADOW, then create automation. This starts no real wallet, transfer, signer or paid subscription. Only the owner-authenticated API can create/pause/resume sessions; global HALT still vetoes fills. Authenticated reauthentication in `/rules` resumes OBSERVE only. Pause automation before changing provider configuration. Policies are immutable; create a new session for a revised policy.

Discovery stores real DEX data and independently attributed Jupiter Tokens V2 recent-first-pool data. Both provider health states remain visible; failure is not hidden by fallback. Jupiter metadata is NOT on-chain pool or token security. Missing liquidity, sell volume, venue or holder proof remains unknown. `/paper` displays LIVE_PROVIDER or REPLAY_TEST source scope separately from PAPER/SHADOW ledger mode. Production worker claims LIVE_PROVIDER only. The test harness refuses any database outside loopback `sentinel_d1_test*`.

Per-mint durable jobs have expiring, token-fenced leases. A unique active-lease index permits only one job per virtual account/session; independent sessions never share capital. Reservation is recorded atomically at claim. Current lease is excluded from its own sizing while all fills/HALT/current ledger checks are serialized by the common advisory transaction lock. On commit, eleven-stage trace, fee-aware virtual fill, journal, exit mark, audit/outbox and lease release are one transaction. On timeout/crash, a new token supersedes the expired lease. An old process cannot commit. Queues are capped at 1,000 historical jobs/session and 20 active sessions per discovery iteration; stale market-only jobs do not starve current observations, owned positions remain eligible for monitoring.

Quote adapter only calls Jupiter `/swap/v2/order` GET without taker/receiver. It requires null transaction/taker, exact mint/amount/slippage/minimum-output binding, fresh request/cost timestamps, known routes and RFQ expiry. No execute or signing function exists in this adapter. Simulated fills use conservative minimum output. Quote-only zero gas fields with null payer do NOT imply free execution. Cost model `CHAIN_SAMPLED_CONSERVATIVE_V1` samples finalized getFeeForMessage for a one-signature no-instruction unsigned message, doubles signature allowance, uses maximum recent priority-unit price at 1.4M compute units, and charges one SPL account minimum rent per attempt. Raw RPC/model facts are stored with quote hash/age. This is a conservative PAPER assumption, not actual transaction fee/rent or guaranteed realizability. All modeled charges are currently expensed into FIFO cost/proceeds; recoverable rent is not assumed. Fee/rent breakdown remains in immutable quote evidence. Separate rent refunds, persistent capital-flow commands, partial exits and full reservation qualification remain open scope.

Existing token security is intentionally strict. Full-holder evidence and supported SPL semantics are required; unqualified pool security also stays UNKNOWN. Thus actual providers can legitimately produce only SKIP during this increment. No risk gate is weakened to create a market BUY. Exit quotes monitor existing positions and refresh estimated liquidation equity; stale/missing quotes make equity/unrealized PnL UNKNOWN. Realized PnL requires a virtual SELL. SHADOW records proposals without inventing fills or inventory. No-trade outcomes are not wins.

## Integrated capital ledger update — 2 November 2026

Migration013 orders fills and capital/rent events in one immutable sequence, backfills existing virtual fills without changing their meaning, and replays the same book after restart/restore. POST `/api/v1/research/sessions/:id/capital` requires owner/service authentication plus normal browser CSRF. Commands require UUID requestKey, positive integer amountLamports and note: DEPOSIT, WITHDRAW, RENT_RESERVE, RENT_REFUND (also original rentReservationKey). All are VIRTUAL_CAPITAL_NOT_CHAIN, never wallet transfers. Retry must reuse the same request key/payload. Refunds cannot exceed the original reservation; cash reductions preserve active worker reservations and policy reserve. Refundable rent stays in virtual equity, not realized profit.

`exitFractionBps` is an optional research-policy field; absent means full exit, preserving historical policy hashes. Fractional size rounds down to integer base units, with minimum one indivisible unit for dust. The ledger supplies exact FIFO basis for that quantity; remaining lots retain rounding remainder. Partial exit requires fresh size-bound quotes and all independent exit checks. Do not scale a partial quote to invent an executable mark for the residual inventory: valuation remains UNKNOWN until a matching fresh exit quote exists. This feature does not qualify any unsupported mint/program or authorize mainnet.

PAPER history is cursor-paginated (default50, maximum100) and includes eventCount/history.nextCursor. Performance metrics still read all session decisions; loading a page never changes sample size. The lab and automation pages expose virtual capital events and bounded history. Quote cost modelV1 still conservatively expenses its estimated network/priority/rent allowance; explicit refundable rent reservations are separate virtual allocations, not a claim that blockchain rent was actually recovered. Actual chain rent/fees require execution receipt reconciliation, which remains unfinished.
