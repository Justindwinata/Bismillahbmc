# Encrypted backup and empty-target restore

This local PostgreSQL drill is implemented and tested. Production key custody, remote TLS, scheduling, storage retention, offsite copies and recovery-time targets still need qualification. Backups do not qualify trading or activate a signer.

Use PostgreSQL client tools compatible with the server, Node/pnpm from the lockfile, an operator-selected output ending `.sentinel.enc`, DATABASE_URL, and BACKUP_PASSPHRASE_FILE pointing to a private (0600) file containing at least 32 high-entropy bytes. Provision/escrow a production backup passphrase through the owner's secure process, never chat, Git or shell literals. This repository does not generate a production passphrase. Losing it makes the encrypted archive unrecoverable.

Run `pnpm ops:backup` with these environment variables supplied locally. It streams pg_dump custom-format output into memory (50 MiB cap, 120-second tool deadline), encrypts with AES-256-GCM, random salt/IV and PBKDF2-SHA256 (600,000 iterations), syncs a private temporary encrypted file and publishes via an atomic non-overwriting hard link. No plaintext dump is written. Existing archives are never replaced; encrypted files are Git-ignored. Keep archives and passphrase in separate protected locations. Remote targets require sslmode=verify-full; remote certificate/host qualification has not been run here.

For recovery, stop the application and create a NEW EMPTY database. Set DATABASE_URL to that empty target, BACKUP_FILE to the chosen archive, BACKUP_PASSPHRASE_FILE to the secure file, and CONFIRM_EMPTY_DATABASE_RESTORE=true. Run `pnpm ops:restore`. It authenticates the complete encrypted archive before pg_restore, rejects nonempty databases, restores in a PostgreSQL transaction, revokes all old browser sessions and wallet nonce proofs, and writes a recovery audit/outbox event. Never start the app if the command fails, including post-restore revocation failure.

Run `pnpm exec tsx scripts/verify-restore.ts` with BACKUP_VERIFY_SOURCE_URL and BACKUP_VERIFY_TARGET_URL for a disposable, quiescent drill. It compares every durable business table's exact canonical row hashes/counts, intentionally excludes revoked auth/session/proof rows and the new recovery audit/outbox entry, checks auth tables are empty, and proves restored audit mutation is rejected. For a historical production recovery without the source database, independently verify archive inventory, audit chain, ledger balances and chain state before starting workers. This script is a drill tool, not complete disaster-recovery certification.

Actual evidence is in evidence/R4/backup. Initial whole-table restore matched; subsequent hardened restore additionally proved session revocation and recovery audit. Wrong passphrase/header/tag/payload tests reject corruption; CLI proves overwrite/nonempty/corrupted-archive rejection. Disposable databases and encrypted fixture archives remain local/ignored; no user wallet keys or funds were involved. No actual long-duration soak or offsite recovery is claimed.
